# BLE 主用、USB 备用与热点恢复

本轮按用户纠正保持 BLE「行者无疆」为默认主连接，新增手动 USB 备用。当前对象为独立 ESP32-S3 / fpga-bread-s3 / N16R8，不是 V3 PCB。本轮没有修改 FPGA RTL、时钟、引脚或 UART 115200，也没有烧录。

## 已完成

- 共用前端与 FPGAvedio 提供 BLE / USB 选择。已连接时锁定模式，断开清理后才可切换；不自动切换、不自动续播或重放 PLAY/STOP。
- USB 使用 S3 原生 USB Serial/JTAG（GPIO19/20），独立于调试 UART0。须选 Espressif 原生串口，不能以普通 USB 转 UART 接口代替；实际 COM 口须上板确认。
- USB 使用带随机会话标记的封装、序号确认和心跳；排除调试日志、旧会话回复和超长输入。桌面只在本地受信页面、用户明确选择后授权端口。
- ESP 的 BLE、USB、语音共享单个 UART 所有权，切换前排空至少 3 秒。USB 无有效心跳 5 秒后释放；超时/断线清队列，已发送到 FPGA 的命令不保证可撤回。
- BLE 仅在特征明确支持时优先 Write Without Response，不在部分发送失败后换 API 重发。SONG2 仍等待 FPGA 编号应答及整曲 CRC/COMMIT；USB 队列应答不计作设备执行。
- 上位机显示上传耗时、FPGA 确认的有效字节速度、重试次数。UART 已有 RX 8192 / TX 1024 环形缓冲，保留其背压机制。
- 桥接泵请求间隔从 10 ms 改为 2 ms。本次构建 `CONFIG_BT_NIMBLE_USE_ESP_TIMER=1`，IDF NPL 的转换保留毫秒值并通过 esp_timer 调度，不受 FreeRTOS 100 Hz 换算截零影响；这不是实际吞吐或调度延迟的测量。
- 已配网时持续等待/重连保存的热点，避免超时后永久切到配网 AP。原依赖按约 10 秒重试，BOOT 配网入口保留；BLE/USB 在等待 Wi-Fi 前初始化。新增网络 connected 状态。

## 使用步骤

1. 正常扫描 BLE「行者无疆」，检查 FPGA 能力，上传并取得提交确认，再播放。
2. 若需要 USB，先停止并确认、断开 BLE，等待至少 3 秒，手动选择 USB 并连接原生 USB 串口。异常拔线可能还须等待 5 秒租约到期和随后的 UART 排空。
3. USB 握手后重新检查 FPGA 能力，按实际状态决定是否重新上传；播放须再次手动点击。恢复 BLE 同样先断开当前链路。
4. 赛前本地识别/整理并保存、导出曲谱，现场无需 Wi-Fi 即可 BLE/USB 上传；小智云语音仍依赖互联网。

## 验证与边界

- 共用前端完整构建及测试 130/130，上一版 124 项保留。新增 BLE 写入与失败不重放、USB 整曲 4096 事件/CRC/播放/停止、会话隔离、超时、串口写入挂起和超长输入覆盖。
- 桌面 BLE/USB 连接模块测试 9 项通过，其中 USB 3 项在清理修正后再次通过。
- 原生 C 测试 bridge_core / voice_core / usb_link 3/3；15 种分片/MTU 组合、1065 次 SONG2 请求/回复，以及 12 条原 RTL 黄金交换通过。
- 真实 MP3/模型/浏览器流程、模拟 USB 字节流握手/关闭/切回 BLE、App 流程通过。实际打包桌面通过模式切换、原生窗口按钮、转谱、三图和 BLE 默认/USB API 检查，无运行时异常。
- ESP-IDF 5.4.4 编译成功，应用 0x2aba80 字节，6 MiB 应用分区剩余约 55%。存在上游 LV_USE_OS 配置和旧触摸 API 警告，不宣称零警告。

候选产物见 `artifacts/ble_primary_usb_backup_20261024/`。应用基址 `0x100000`，完整地址以配套 flash_args 为准。没有打包设备 NVS、激活身份或 Wi-Fi 密码，没有改写已验证 stage64 镜像。新板完整刷写与旧板仅更新应用须先核对分区及硬件配置，不能混用 V3 PCB 镜像。

本轮没有硬件 BLE/USB、热点断开恢复、实际速度或音质测量，没有生成新 APK。没有实现 ESP Flash 歌曲缓存或本地离线语音识别；FPGA 歌曲 RAM 断电仍丢失。软件测试和固件构建不能代替这些上板验证。

# FPGAvedio 使用与演示

电脑应用保留原播放器模式，并提供 FPGA 播放模式。左侧功能导航按流程跳转；右侧 BLE 连接；三种图形分开显示，板端联动图形放在后部。

1. 准备曲目：导入有权使用的普通音频/MIDI，或从播放器当前歌曲进入 FPGA 工作台。平台仅开放试听或拒绝音频时，不代表可以获取完整歌曲。
2. 转谱/预览：音频在本地识别为音符，可选择范围、调门槛并试听。复杂人声/伴奏可能导致音高/节奏错误，优先用清晰旋律验证；MIDI 或准确曲谱通常更可靠。
3. 旋律整理：确认选段、力度与容量，试听整理后的实际上传版本；原识别结果保留。容量以真实设备 CAPS 为准，不静默截断。
4. 连接右侧 BLE，选择“行者无疆”；识别设备、读取上传能力。仅连接成功不等于 FPGA 已响应。
5. 上传并等待所有分块及整曲 CRC/COMMIT ACK，之后单独点击播放。丢包重试、取消与超时按协议处理，不用本地计时假装板端已执行。
6. 检查 LCD/灯带和实际声音。上传保存在 FPGA RAM；断开电脑后可以继续，断电则丢失。

## 两种可视化

- 本地试听波形/频谱/李萨如：来自电脑端试听，不表示 FPGA 在发声。
- FPGA 联动：琴键/状态由真实板端回包更新；波形、频谱、李萨如来自 SCOPE1 有限音频快照，必须连接并取得真实数据。不承诺持续实时音频流。

## 注意

MP3 不会以原声上传，而是识别音符后用 FPGA 音色重奏。音质、识别正确率、无线吞吐须分别验证。Android 源码在 `host/mineradio/android`，签名私钥不上传；重建不同签名不能覆盖旧安装。电脑打包入口是 `npm run build:fpga:dir`，不是上游自动发布配置；本派生版自动更新已禁用。

子目录原 README 保留上游和历史记录，其中 stage59b、512 事件、9600 和“255 音符”等旧描述不代表 stage64 的当前容量/串口设置；当前状态以根 README、docs/RELEASE.md 和设备 CAPS 为准。

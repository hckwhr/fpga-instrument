# 纯音乐复音转谱优化（2026-10-24）

## 问题与改动

基于用户从开头录制的板端声音与原曲对比，现有证据未见明显累计节奏漂移；主要问题在上位机整理：同一时刻的和弦被筛成单音，后来的音符截短前面的长音，低音还影响整段的八度映射。录音的稳定段主导音高匹配率不代表原曲还原率。

新默认“和弦与延音 · 推荐”保留识别出的和弦、重复起音和长音，不再因下一音开始而截断。板端原生 MIDI 48–83 范围内音高不变；超范围的低、高音区分别采用统一八度移动，无法容纳的部分明确报告。保留“单声部旋律 · 旧版兼容”，旧模式结果不变。

生成曲谱划分为“显示引导（单声部）”和“和弦与延音（复音）”两轨。LCD 使用前者，实际播放两轨；每个音符只属于一轨，不重复发声，也不为适配显示截短实际长音。原始识别结果不被修改。

沿用既有严格编译器：4096 事件、通常至多 2048 个完整音符，每拍事件密度、同时占用声部（含释放尾音）和总力度均检查。满容量时优先保留各起音组并覆盖全曲，删减数量明确显示；起音组本身超容量则要求缩短选段。为界面 125% 力度设置保留余量，不以取消校验换取播放。

## 同一曲目的离线对照

测试曲目选段为 235.051 秒，原识别音符 2486 个。下表是转谱和编译结果，不是实物音质评分。

| 项目 | 旧单声部整理 | 新复音整理 |
| --- | ---: | ---: |
| 保留音符 | 1534 | 2048 |
| 事件数 | 3068 | 4096 |
| 被下一音截短 | 987 | 0 |
| 最大占用声部（含尾音） | 3 | 8 |
| 音符时长之和（秒，含重叠） | 217.1625 | 526.76875 |

新整首结果有 36 个同音近起音重复被合并去重，另有 402 个音符因容量省略；并非无损保留全部识别结果。引导轨 779 个音符，伴奏轨 1269 个。原生范围内音高不整体移动。

前 30 秒识别的 222 个音符全部保留：引导 76、伴奏 146，444 事件，最大占用 8 声部；容量、密度、音区和边界省略均为 0。其中 17 个超原生音区音符做八度移动，其余 205 个音高不变。

具体例子：原识别 MIDI 72 从 0.975 秒持续至 2.010 秒，旧整理在 1.05625 秒就释放，新整理在量化后的 2.0125 秒释放，并保留同时开始的 MIDI 62 和声音符。

## 复测步骤与限制

1. 完全退出并重启桌面 FPGAvedio。
2. 重新生成曲谱，保持“和弦与延音 · 推荐”；或在曲谱库导入本机 `artifacts/instrumental_polyphony_20261024/first-30-seconds.fpga-score.json`，先做同一首歌前 30 秒对照。
3. 使用“试听 FPGA 演奏参考”，确认两轨均选择，再上传并等待 CRC/COMMIT 确认，播放速度设为 100%。
4. 重新录制板端输出，比较和弦、长音与原曲旋律。旧存档和 FPGA RAM 中的旧曲谱不会自动更新，必须重新生成或导入并上传。

此改动修正转谱整理造成的信息丢失；仍由既有模型识别音符、由 FPGA 钢琴音色重奏，无法保证原曲配器、鼓点和音色还原。本轮新曲谱尚未完成实物 A/B 试听，不宣称已听到或证实板端音质改善。

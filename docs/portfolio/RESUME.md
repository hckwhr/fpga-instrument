# 简历项目描述

项目名称：**灵弦——基于 FPGA 的实时多音色合成与交互演奏系统**

项目链接：https://github.com/hckwhr/fpga-instrument

以下提供不同岗位的写法，选择一版即可。条目中的工作须与本人实际分工一致；项目时间、担任角色及个人负责模块按真实经历填写。

## FPGA / 数字 IC 前端方向

**技术栈：Verilog、Gowin GW5AST-138C、ModelSim、RTL 仿真、STA、CDC、UART、HDMI。**

- 构建 12 路压力键交互乐器，接入双轴摇杆表情控制；实现 32 独立声部与 8 路物理弦声音引擎，完成音符事件、声部分配、包络、混音及 PT8211 音频输出。
- 按音频采样槽共享算术资源，保留各声部独立相位和包络；将 HDMI 六字段十进制转换移至帧前串行预计算，78 拍完成，配合冻结参考核对字形和像素行为。
- 构建从 ADC/UART/设置键引脚到音频及 RGB 输出的回归；基于综合网表验证共同 CE 多周期约束与压缩集合等价，覆盖复位、提前使用、换帧和异常输入。
- 最新 HDMI 单屏版本通过 163 项 RTL 回归和 3 项官方器件模型测试；完成布局布线，setup/hold 为 +0.556/+0.187 ns，建立与保持违例为 0，Logic 使用量 72539/138240。

这版适合投递 FPGA 开发与数字逻辑岗位。实际使用时可将第二、三条收敛到自己最熟悉的一项优化，避免一句话塞入过多技术点。

## 嵌入式 / 软硬件系统方向

**技术栈：C/C++、ESP-IDF、ESP32-S3、BLE、USB、UART、JavaScript、Electron、Android、Verilog。**

- 集成 FPGA 声音引擎、ESP32-S3 桥接与 Windows/Android 上位机，打通压力键演奏、曲谱上传、播放控制及声光反馈链路。
- 实现 BLE 主连接与 USB 手动备用，利用行组包、环形队列和会话控制转发 UART；以 FPGA 事务应答、分块确认及 CRC 判断上传结果，处理断线、超时和语音/上位机链路竞争。
- 基于 Mineradio 扩展 FPGA 工作台与 12 轨节奏跟练，复用跨端曲谱处理逻辑；集成 MIDI/音频转谱、容量检查、参考试听与板端状态回传。
- 建立协议、页面交互和引脚级验证，排查后台轮询占用导致按钮闪烁及操作阻塞；最新 FPGA 配套版本通过 163 项 RTL 回归，完成时序验收。

嵌入式岗位优先展开通信状态机、队列边界、应答语义和失效恢复。云端语音写“接入小智服务”，音频识别写“集成与适配”，不写成自研语音模型或自研音频识别算法。

## 精简版：简历只留三行

**灵弦｜FPGA 多维交互数字乐器**

基于 GW5AST-138C 实现 12 路压力键输入、32 声部合成与 8 路物理弦，联动 HDMI/RGB；通过 ESP32-S3 接入 BLE/USB 曲谱上传及桌面/Android 应用。完成引脚级仿真、共同 CE 约束审计及布局布线，最新版本 163 项回归通过，setup +0.556 ns、hold +0.187 ns。

## 数字用法

“32 复音”描述合成引擎的独立声部数，不表示上传曲谱准入允许 32 个同时音符；当前曲谱编译包含释放尾音在内的 16 声部限制。4096 是事件容量，不是完整音符数。

163 是最新 RTL 回归数量，3 是单独的官方 HDMI 模型数量。它们不能换算成代码覆盖率，也不能代替实物测试。最后一版位流已生成但未烧录，面试中按此说明。

不使用“72 复音”“原生 1080p”“无损 MP3 播放”“自研语音大模型”“全系统任意条件下零抖动”等描述。延迟示波器图片已保留，简历若要加入延迟值，须同时明确测量起止点与测试模式；本稿不把局部测量扩展为全链路保证。

# 音符事件接口第一步

本轮为歌曲播放器增加命名一致的起音、保持、音高和力度接口，作为后续音符事件改造的兼容入口。不改变当前歌曲、音源、效果器、LCD 或引脚。它还不是通用多声部事件总线。

## 合同

事件工作在 `audio_clk` 域，以 `sample_strobe` 为采样边界：

| 字段 | 宽度 | 含义 |
|---|---:|---|
| `event_valid` | 1 | 一个音符起音脉冲，只在 Note On 时为一个采样槽 |
| `event_gate` | 1 | 音符保持状态；变为 0 表示释放，不产生新音符 |
| `event_voice_id` | 6 | 当前固定为 0，顶层尚不使用；未来需明确编号与分配器的关系，当前没有 32 声部事件寻址 |
| `event_note` | 4 | 十二平均律音高类别，0=C、1=C♯……11=B；不是 MIDI 绝对音高 |
| `event_octave` | 2 | 八度 |
| `event_force` | 7 | 0～127 力度 |

`song_player.v` 保留 `trigger/gate/note/octave/force_level` 作为兼容端口。新字段为旧输出的组合别名，顶层歌曲的音频路由消费新字段；LCD 的八度仍使用等值的旧别名。没有新增 FIFO、时钟域、延迟或声部寻址逻辑。

`event_valid` 只表示起音，一个采样槽内保持高电平；不能把它当作每个 audio_clk 都消费一次的总线 valid。`event_gate` 是声部 0 的持续电平，停止/退出可以在采样间隔中将其清零；消费者在其采样节拍处理释放。它无法仅凭这两个信号表达交错的多声部 Note Off，后续必须定义有明确接收时刻的事件类型、音符身份及排队/流控机制。

当前限制：歌曲仍是固定 42 音符《小星星》，`event_voice_id` 仍为 0，尚未加入多声部曲谱 RAM、Note Off 事件队列或上传协议。

普通按键、32 复音和物理弦仍使用原有入口，尚未统一。通用曲谱对接时仍需要改造事件路由和声部分配器，不能声称本轮已支持任意 MIDI 或多声部伴奏。

## 验证

`tb_song_player` 逐个音符检查统一事件与旧端口完全一致，并检查保持期间 `event_gate` 一致；原有 42 音符时序、释放间隔、停止、重播和重新进入测试继续执行。

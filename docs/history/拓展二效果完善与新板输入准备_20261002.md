# 拓展二：效果器完善与新板输入准备

版本：`effects_ready_20261002`。目标：Tang Mega 138K SOM 30354 + Dock 31005，
`GW5AST-LV138PG484AC1/I0`，Gowin V1.9.12.03。
本轮证据级别为 **bitstream-generated**，尚未烧录、尚未经过音箱听测。

## 这次可以直接在现有板上体验的内容

1. 音效增加“混响”。FPGA 内四条不同长度的阻尼反馈延迟线产生较短的空间尾音；
   这是实时算法，不使用录音播放。延迟、合唱、混响单选，避免组合时难以辨认效果。
2. 合唱使用相邻采样点的分数插值，减轻延迟抽头跳动引起的台阶。保留原有明亮音色。
3. 延迟和效果混音保留幅度余量。启用效果后直达声系数为 1/2，正常演奏时可能比原声轻；
   可用音箱旋钮调听音音量，不用数字削顶换取响度。旋钮位置仍不能由 FPGA 检测。
4. 切换音效／菜单静音使用 128 个采样的增益过渡（约 2.67 ms），重新开始时屏蔽旧 RAM。
   这是效果器切换处理，并不等于所有上游音色和源切换都已证明绝无瞬态。
5. 一个“对比试听”选项覆盖七组对比。基础页、拓展页仍各六行，不再增加设置页面。

## 验证操作

按 S2 → 页签选“拓展要求” → KEY0 移到“对比试听”。
KEY1 循环选择目标，KEY2 显示“准备”，S2 返回演奏页开始。
每次相同的 C–G–C 乐句：A 段 4 秒，B 段 4 秒，循环播放。S2 停止并回设置。
更换目标会取消准备；只改目标后要再按一次 KEY2。

| 目标 | A 段 | B 段应关注什么 |
|---|---|---|
| 滑音 | 直接换音高 | C 与 G 之间连续滑动 |
| 颤音 | 稳定音高 | 持续音高周期摆动 |
| 延迟 | 短促琴音 | 每个音后出现间隔约 128 ms 的逐渐减弱回声 |
| 合唱 | 短促琴音 | 声音更厚，带缓慢变化的重叠感；单声道不能体现立体声宽度 |
| 混响 | 短促琴音 | 音后出现短空间尾音，与一声声可数的延迟不同 |
| 力度 | 三个音均用力度 96 | 三个音分别用 32、80、127，呈现弱、中、强 |
| 琴弦 | 波表琴音 | 物理弦模型，关注拨弦起音与衰减；两种算法本身响度不同 |

延迟／合唱／混响的 A 段也将原声减半，以匹配 B 段的直达声系数；
这不表示 A、B 总能量相同，湿声叠加本来会改变能量。
对比声源直接经过正式 `av_top`、合成器、效果器及 PT8211 输出链路。
仿真导出的 WAV 只供分析，不会放入 FPGA 当作播放素材。

正常演奏的音效在“音效”一行选择：原声／延迟／合唱／混响。
32 合音、32 复音测试仍使用原先的直接输出，不叠加效果以保持测试可解释。

## 新硬件的软件边界

已增加 `performance_controls.v`，接口工作在 `audio_clk` 域：

| 输入／输出 | 合同 |
|---|---|
| `frame_valid` + `force_raw/x_raw/y_raw` | 每帧一个时钟脉冲；同一时刻提供完整 10 位 CH0/1/2 数据 |
| `force_zero`、`force_gain_q12` | 零点扣除后按 Q12 系数映射到 0～127；允许校准、饱和保护 |
| `x_center/y_center` | 摇杆实测中心；默认 512 只是初值 |
| X 轴 | 中心死区、平滑到有符号弯音值；当前频率比例约 -12.5%～+12.4%，不是对称半音标尺 |
| Y 轴 | 按偏离中心的幅度选择关闭／三级颤音深度 |
| 力度 | 帧间低通、逐采样平滑；整数滤波可能残留最多 3 ADC 码的偏差，应纳入端点标定 |
| `pressure_gate/pressure_trigger` | 迟滞按压状态与一次起音脉冲；持续按住不重复触发 |
| `sensor_ready` | 超过 4800 个音频采样未收到帧（约 100 ms）失效，清按压状态并回退手动控制 |

三个维度可同时参与普通四声部 DDS 运算，不需要切换互斥模式。
界面的滑音／颤音预设仍为便于演示而分开。力度接口已接到普通 DDS、32 复音和琴弦；
弯音／颤音目前只进入普通 DDS，未宣称物理弦和 32 复音已有相同的连续调音能力。

当前板 `sensor_enable=0`，因此传感器分支会被主工程综合优化掉；
另建独立综合探针证明该模块不是只能仿真的代码。没有在未核对的新引脚上输出信号。

新板回来仍要完成：

1. 以实际交付 PCB 核对连接器、引脚和 3.3 V 电平。现有硬件文档存在不同阶段方案，不能混用。
2. 根据 MCP3008 原厂时序接入 SPI 采集；如果跨时钟域，整帧经握手或 FIFO 传递，不能逐位同步。
3. 将压力起音／释放接到选音和声部分配器，明确与机械按键触发的优先级。
4. 采集 FSR 空载和受力端点、摇杆中心和范围，写入校准值。
5. 对真实琴键扫描、LED 驱动、噪声、连按、失联释放和输入到模拟音频延迟做联调。

因此这轮准备能减少算法重写，但不能保证新板到手只改几行代码就完成全部硬件验收。

## 验证证据

13 个 ModelSim 测试通过：
`tb_performance_controls`、`tb_audio_effects`、`tb_effects_audition`、
`tb_expression_audition`、`tb_pitch_expression`、`tb_settings_pages`、
`tb_dynamic_strings8`、`tb_audio_voice_mixer`、`tb_polyphony_bank_32`、
`tb_lcd_pipeline`、`tb_lcd_polyphony_count`、`tb_smooth_audio`、`tb_physical_strings`。

- 288 组关闭表情的 PCM 对照与原基线一致。
- 效果器测试包含正负 30000 PCM 输入、脉冲、静音、旧 RAM 屏蔽和零输入尾音退净。
- 正式顶层五组新增 A/B 均产生不同 PCM；峰值 2883／3966／2635／6904／5270，均未削顶。
- 力度 B/A 对应音段 RMS 比约 0.3333／0.8333／1.3348；这是数字仿真数据，不是音箱测量。
- 混响脉冲首反射约 31.23 ms；绝对值大于 4 PCM 的最后反射约 400.56 ms。
  此阈值结果不等于房间声学 RT60，也不能单凭它判断主观听感。
- 独立传感器综合：306 Logic、61 FF、0 Latch；仅综合，没有引脚布线或板上验收。
- 主工程综合、布局布线、位流生成通过；setup 最差 +0.068 ns，hold 最差 +0.181 ns。
- 最终资源：38967 Logic、10095 FF、70/340 BSRAM、144/298 DSP、0 Latch、33 I/O。
- 时钟覆盖和引脚审计通过，CST/SDC 与原版一致。时序余量仍偏小，后续增加接口必须重新收敛。
- 新增的 5 条位宽告警来自梳状滤波均值和四路混响均值缩回 16 位；
  每项均为有界平均，最大范围仍在 16 位内，仿真已检查正负输入。其余旧告警保留在构建日志中。
- 主工程传感器模块被裁剪的告警符合 `sensor_enable=0` 配置；独立综合无此裁剪。
- 工具开头出现 IDE 全局缓存 `sh.log` 无法打开的提示；项目本地构建日志、综合报告和位流均已成功生成，未将该缓存提示当作 RTL 错误。

原有滑音／颤音测量见 `expression_ab_preview/measurements.json`。

## 对照题目，下一阶段的边界

拓展二的效果算法和三维控制逻辑已经具备软件／RTL 证据，真实三维演奏仍待新板。
当前软件并非整个赛题所有拓展均已完成：拓展三的实时频谱、李萨如图、低延迟扫描链，
以及拓展四的脱机曲目指引仍应分别开发验证。波形显示已经存在；HDMI 和蓝牙没有纳入这轮。
推荐接下来先做拓展三的实时可视化，并把低延迟采集接口和曲目事件格式与新板联调统一，
不继续增加难以辨别的音色模式。

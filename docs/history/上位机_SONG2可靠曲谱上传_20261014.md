## 用户操作与边界

连接 BLE/串口 → 检查上传能力 → 导入 MIDI 或打开存档、选择轨道/速度/力度及 LCD 单声部旋律轨 → 上传当前曲谱。仅匹配本次 CAPS 请求的 ACK 能启用上传，每次实际上传还会重新查询能力。

页面进度只累计 DATA ACK 确认的事件字。进度到 100% 时仍须等待 COMMIT ACK；成功文字为“设备已确认整曲 CRC 与提交；尚未请求播放”。扩展 CAPS 确认播放能力后，可用新增的“播放已上传曲谱／停止上传曲谱／查询上传曲谱状态”。原内置曲目 PLAY/STOP 按钮保持原用途。网页显示最近一次设备应答，不能据此宣称实际扬声器已发声。

stage42 的 HELLO 明确不含上传能力。对其执行新能力检查会超时，需要断开重连后再使用旧短命令；网页不会将 `ERR,LINE` 或串口写入成功作为上传应答。

曲谱沿用 ABI 12：64 位字、绝对 6.25 ms tick（板端速度 100）、512 事件、同刻最多 16 事件、含尾音最多 16 声部、力度和 768、旋律最多 255 音。界面按当前预览相同的整数毫秒时间与力度缩放编译；未选轨道不进入上传。网页上传结束时间取最后一个音符关闭，**不保留 MIDI 文件末尾的空白休止**。离线 ROM 导出继续使用原始 tempo map/轨道结束时间，原两首曲谱基线未改变。恢复的库存档无 tempoMap，也能按音符毫秒字段编译。

存在不支持的控制器、鼓轨、越界音高或转谱警告时继续拒绝 FPGA 编译，不静默删音或删除警告。音频转谱当前总带识别警告，因此仍需后续音符校订/明确审阅流程，不能直接上传任意识别结果。

## 字节与编号合同

ASCII 大写，发送 LF，接收可容忍 CRLF；发送整帧（含 LF）≤256 字节。十进制字段无前导零，十六进制字段大写、定宽。

- `sid`：浏览器安全随机数生成的 64 位会话号，16 位十六进制。每次能力检查/上传事务均生成新号，不是账号或身份认证。
- `seq`：0..65535 十进制请求号。同一事务 CAPS=0，后续每个新请求加一；停止等待，每次只有一条请求。重试使用原帧、原编号。
- `FCRC`：CRC-16/CCITT-FALSE，初值 FFFF，多项式 1021，非反射，xorout=0000；覆盖整行从前缀至最后一个有效字段的 ASCII，**不含最后的逗号、CRC 字段、CR/LF**。请求与响应均带 CRC，编号与元数据也受保护。标准向量 `123456789` → `29B1`。
- `SCRC`：同算法，覆盖所有事件字按顺序、每字大端 8 字节拼接的原始二进制。元数据受各帧 FCRC 保护。
- `N`：1..512 事件字；`T`：1..16777215 结束 tick；`M`：1..255 旋律音数；`K`：设备声明每块 1..8 字；`O`：起始偏移；`C`：本块字数；`HEX`：每字16个十六进制字符。

| 操作 | 请求（省略结尾 LF） | 成功应答（省略结尾 LF） |
|---|---|---|
| 能力 | `SONG2,sid,0,CAPS,FCRC` | `ACK2,sid,0,CAPS,12,Nmax,K,FCRC` |
| 开始 | `SONG2,sid,seq,BEGIN,12,N,T,M,SCRC,FCRC` | `ACK2,sid,seq,BEGIN,0,FCRC` |
| 数据 | `SONG2,sid,seq,DATA,O,C,HEX,FCRC` | `ACK2,sid,seq,DATA,OplusC,FCRC` |
| 提交 | `SONG2,sid,seq,COMMIT,N,SCRC,FCRC` | `ACK2,sid,seq,COMMIT,N,SCRC,FCRC` |
| 取消 | `SONG2,sid,seq,ABORT,FCRC` | `ACK2,sid,seq,ABORT,FCRC` |
| 播放能力 | `SONG2,sid,0,CAPS,FCRC` | `ACK2,sid,0,CAPS,12,Nmax,K,1,FCRC` |
| 播放上传曲谱 | `SONG2,sid,seq,PLAY,N,SCRC,TEMPO,FCRC` | `ACK2,sid,seq,PLAY,STATE,NOTE,N,SCRC,VALID,STOREDCRC,FCRC` |
| 停止上传曲谱 | `SONG2,sid,seq,STOP,FCRC` | `ACK2,sid,seq,STOP,STATE,NOTE,N,SCRC,VALID,STOREDCRC,FCRC` |
| 查询上传曲谱 | `SONG2,sid,seq,STATUS,FCRC` | `ACK2,sid,seq,STATUS,STATE,NOTE,N,SCRC,VALID,STOREDCRC,FCRC` |

错误响应：`ERR2,sid,seq,operation,CODE,FCRC`。CODE 为 `BUSY/CRC/ABI/CAPACITY/SESSION/SEQUENCE/CONFLICT/OFFSET/FORMAT/STATE/CONTENT/NOSCORE`；NOSCORE 表示没有已提交曲谱。CRC 错误或字段损坏导致编号不可信时，接收器应丢弃该帧，不凭损坏编号修改状态。S3 只转发 FPGA 的 ACK/ERR，不生成同名成功应答。

stage45 扩展约定：

- 只有第四个 CAPS 值 `1` 才开启上传曲谱控制；主机仍接受旧版三个值的上传能力。`CONTROL_ENABLE=0` 保留旧上传组件接口行为。
- `TEMPO` 为原调度器 0..3 档；网页固定发送 1（100%），因为速度已在编译曲谱时应用。PLAY 请求长度和 CRC 必须匹配已提交存储；主机也核对 PLAY ACK 的播放长度/CRC 和存储 CRC。
- `STATE`：0 空闲、1 准备播放、2 播放中、3 已结束、4 调度故障；`NOTE` 为 0..255 音符序号。应答 `N/SCRC` 标识播放器持有的快照，`VALID/STOREDCRC` 标识当前发布存储（VALID 为 0/1）。从未载入播放快照时 N=0、STATE=0、NOTE=0、SCRC=0000；STOP 后可保留最近快照身份。存储无效时 STOREDCRC=0000。16 位 CRC 可能碰撞，不是唯一曲目 ID 或安全认证。
- 同 sid/seq 的完整请求重试重放完整 ACK，不重复 PLAY/STOP。STATUS 重试也返回原查询快照；刷新状态必须使用新 seq。只有成功命令消费编号；主机收到明确控制拒绝后复用该编号修正请求。
- 控制沿用上传后的 sid，避免触发 COMMIT 后 30 秒新 sid 保护。暂存过期不妨碍已发布曲谱的 PLAY/STOP/STATUS；旧 BEGIN/DATA 仍拒绝。
- 控制 ACK 来自音频域执行/状态回传。音频时钟停止时请求保持在途，不提前应答或释放播放锁；主机超时标记结果未知并要求重连。STOP 表示停止事件并释放声部，尾音不会保证在 ACK 时立即静音。断线也不代表停止演奏。

SONG2 与旧 SONG/SONG1 预览格式分开。旧 `encodeUploadFrames` 保留用于历史离线预览；实际事务使用 `score-upload-protocol.js`。CRC 用于检错，不是安全认证。

## 接收器实现要求（stage43 起实现，stage47 逻辑整合）

1. 接收完整有界行、检查格式/FCRC、编号和状态，再改 RAM。CAPS 只声明实际已可用的 FPGA 能力，不能仅凭 S3 的 BLE 连接返回成功。每次只允许一个暂存上传事务。
2. BEGIN 分配暂存区，不能清除已经提交/正在使用的曲谱。DATA 只允许连续偏移，完整检查本块后写入，ACK 的 OplusC 表示已可靠写入的下一偏移。
3. 同一 sid 的最近已接受请求需保留请求内容和响应。完全相同的 sid/seq/内容重发只重放响应，不重新 BEGIN、写 DATA 或提交。相同编号不同内容报 CONFLICT；旧序号报 SEQUENCE。比较完整请求内容，不能仅比较 16 位 CRC（有碰撞）。
4. ABORT 特许跨过缺失请求号：丢失的 BEGIN/DATA 可能根本未被接收，仍须允许后续更高 seq 清理该 sid。不存在暂存时返回幂等成功；不能清理另一个 sid 的暂存，不能撤销已经提交的曲谱。COMMIT 之后的重复 COMMIT 在缓存保留期内仍返回原成功应答。
5. COMMIT 必须检查已收 N、全量 SCRC、ABI 事件合法性（时间排序、同刻分组、音符配对/结束、旋律计数、容量与播放边界），然后原子发布。校验失败保留旧已提交歌曲，不能自动播放。当前 JS 模型只验证传输/存储 CRC，不实现完整 ABI 事件扫描。
6. 接收器的 session/响应缓存必须有界。当前 JS 模型为故障测试保存 Map，不是可直接移植的固件内存方案。后续实现需确定暂存超时、会话退役与重连清理；建议暂存闲置 30 秒清理，保留 COMMIT 重放记录至少覆盖 30 秒重试窗口；失效会话返回 SESSION，不能重新执行其旧操作。S3 断线/重连必须清空旧转发缓存，不能让旧连接残帧进入新事务。

stage43 的具体边界：只维护一个当前 sid 和最近一次成功请求的完整原始帧（最多 255 字节），不保存任意历史会话。DATA 完整解析后逐字写入，全部写完才 ACK；COMMIT 完成 ABI/CRC 扫描及播放锁检查后才 ACK。不同内容即使 FCRC 碰撞也报 CONFLICT。暂存默认 30 秒无实际存储命令后过期，旧 BEGIN/DATA 重试不能刷新存储期限，过期返回 SESSION；ABORT 可清理当前会话再继续。格式/CRC 损坏直接丢弃。相同请求比较的是去掉 CR/LF 后的原始 ASCII 字节。

COMMIT 成功后默认 30 秒拒绝其他 sid 的 CAPS（BUSY），以保护停止等待协议的提交重试。期间允许当前 sid 后续命令，后续成功命令会替换“最近成功请求”缓存，因此更早的 COMMIT 不再重放；没有后续成功请求时，原 COMMIT 缓存可保留超过 30 秒。保护期结束只允许新 CAPS 接管，不会清除已提交曲谱。上位机当前每次能力检查/上传都生成新 sid，因此刚提交后再次检查能力或上传可能收到 BUSY，等待保护期结束即可。该有限缓存不是永久重放防护或身份认证；S3 仍必须在断线重连时清理旧数据。

## 上位机异常处理

- ACK 必须同时匹配 sid、seq、operation，以及 DATA 的下一偏移或 COMMIT 的 N/SCRC；坏 CRC、超长行、非 ASCII、未知响应、回显和旧会话响应不完成请求。
- 写入完成与 ACK 均满足才推进。默认写入上限 5 秒；写入完成后等待 ACK 3 秒，最多重试 2 次。写入未完成或失败时禁止追加重试/ABORT，并锁定连接，要求实际断开重连。不能用 JS 超时假装底层发送已被取消。
- 取消在 CAPS/BEGIN/DATA 阶段可用。等待当前写入/ACK 结束（取消后不再重试当前数据），再发 ABORT；ABORT 本身可按同编号重试。收到 ABORT ACK 后才显示“已确认丢弃”。COMMIT 阶段不提供取消，防止承诺撤销已发布曲谱。
- 提交应答超时、写入失败、断线或取消未确认：结果未知。即使模型显示设备已提交，网页也不猜测成功。stage45 可在重连并成功检查扩展能力后查询存储有效位/CRC 和播放快照；新 sid 仍可能需等待 COMMIT 的 30 秒保护期。该查询不能还原已丢失的历史 ACK，也不以 CRC 冒充唯一身份。
- 上传期间独占传输层，旧 HELLO/PING/PLAY/STOP/STATUS 和手动调试发送均互斥。断线/原始调试/会话失效清除能力缓存；旧写入 promise 晚到不影响新事务。上传开始前快照为不可变帧，期间编辑页面不改变在途内容。

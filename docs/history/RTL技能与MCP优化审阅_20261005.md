## Ross：把工具证据串成工程闭环

核心价值在技能与工具分工：技能负责选择操作、解释报告、决定下一步；MCP 提供可观测的工具状态。仓库中的 Vivado MCP 是接口文档，服务器需从 AMD 单独下载，不是可直接移植的开源服务器实现。

实际审阅的重点：

- `skills/vivado-simulate-rtl/SKILL.md` 的判定、诊断和重跑段：编译、展开、终态 PASS、全部测试完成、无异常断言／超时必须同时成立；RTL、测试台、环境、超时、工具缺陷分开定位。
- `skills/vivado-rtl-lint/SKILL.md` 与 `parse_lint_report.py`：按工具原始信息生成结构化诊断；ASCII 表按真实列边界处理，避免字段内的 `|` 破坏解析。源码人工评审与工具报告不混为一谈。
- `skills/vivado-timing-methodology-checks/SKILL.md` 的分组、取证和逐组复核：先弄清约束和时钟问题，再修对应路径，而非见负余量就盲目插寄存器。
- `skills/hls-optimize/SKILL.md`：可测基线→假设→一个可归因的改变→读报告→保存结果。区分周期延迟与实际时间；失败尝试也应留证据。
- `skills/hls-run-flow/SKILL.md`：区分 C 仿真、综合、协同仿真、实现的不同证据。
- `docs/reference/vivado-mcp-tools.md`：长任务执行和 status/log/history 分离，运行过程中仍能查询；只读观察不等于重置任务。
- `docs/local-kb/README.md` 的架构说明：领域资料检索与推理分离。本项目已有本地官方手册索引，当前无需引入完整 RAG 服务栈。

适配时没有照搬：Vivado 任意 Tcl 接口、XDC／专有检查编号、远程计算、强制每轮提交、固定 10% 收益或 60% 资源阈值、报告大小门槛。对 Gowin 的判断必须使用本机版本与实际报告。

## Verilog Generator：行为契约与验证预期

审阅 `SKILL.md`、`references/workflows/workflow-contracts.md`，以及
`scripts/python/existing_rtl/semantic_contract.py`、`verify_repair_core.py` 的契约审计／修复入口、测试台生成和验证路径。

值得吸收的是：生成前明确端口、复位、接受事务的边沿、流水周期与边界；参考向量具有稳定标识和哈希；参考模型重复执行必须确定；期望值、中间观测点和 RTL transcript 可以关联定位；不同阶段不应悄悄改变接口或向量。

对当前音频工程的意义：验证“每采样时隙必须准备好新频率”比仅看波形变化更可靠；分配、抢占、清空、停用和重启时，必须检查流水中的旧数据是否会泄漏到新声部。旧版 PCM／状态逐周期对照本来就是本工程已有的有效方法，本次将其明确为可复用规则。

没有引入其整套运行时：强制 Python 中间生成层、每个模块必配 WaveDrom、统一三进程 FSM、组合逻辑固定三操作上限、严格命名前缀和逐行注释，不适合作为现有工程的一刀切标准。其 Xilinx 原语目录也不能验证 Gowin 原语。保留 Verilog-2001／SystemVerilog 的实际工程设置及现有 ModelSim。

## HLS Generator：吞吐量、存储与数值范围一起设计

审阅 `SKILL.md`，`references/hls-report-driven-optimization.md`、
`hls-task-parallel-strategy.md`、`hls-modeling-strategy.md`，以及
`scripts/python/validation/stage_verifier.py`、`hls_reports.py` 的关键接口与解析入口。

其可迁移价值不是“把乐器改写成 HLS”，而是：

- 区分延迟、启动间隔和吞吐量；瓶颈可能是反馈依赖、存储端口、带宽或时序。
- 并行运算要同时检查数据供给和输出消费速度；FIFO 深度、背压、所有权和重启语义属于架构。
- 固定点位宽应由数值范围、舍入和饱和方式推导，测试覆盖边界。
- 阶段校验可以区分规格错误、依赖错误、测试台错误和当前模块错误，避免所有失败都改 RTL。

没有移植 Vitis C/C++、`ap_fixed`、`hls::stream`、HLS pragma 或远程 SSH 依赖。也没有把综合估计值当作真实布线性能。

## 已落实的本地变更

本机没有独立安装的 Verilog Skill；现有规范位于共享 `gowin-fpga/references/verilog-coding-style.md`。本次就在这个真实入口更新，避免创建另一份相互矛盾的规则。

技能修改：

1. 补充接口／时序／数值契约与独立自检要求；测试台骨架、lint 和仿真通过分开报告。
2. 新增按需参考 `report-driven-rtl.md`，记录假设、瓶颈、分阶段验证、构建成本和失败尝试。
3. 更新 Gowin 开发与 MCP 指引，长构建优先异步启动、按 ID 查询。
4. 修正烧录指引与用户偏好的冲突：沿用工程已验证配置和永久 Flash 选择，不强制先做 SRAM 下载或重复确认。

MCP 升级为 0.3.0，独立实现，未复制上游运行时代码：

| 接口 | 实际行为 |
|---|---|
| `gowin_start_build` | 固定 syn/pnr/all，立即返回 ID，独立后台工作进程继续构建 |
| `gowin_build_status` | 持久记录、心跳、耗时、预算、源码／产物一致性，支持客户端重启后查询 |
| `gowin_diagnose_log` | 原始行号、精确错误／告警总数、分类、首个错误、最后进度及日志更新时间 |

同一工程目录只有一个受管构建。预算仅告警；兼容阻塞接口等待超时后返回任务 ID，不能自动杀进程。心跳过期标记 unknown，既不误称成功，也不据此自动重启。
开始和结束核对输入哈希，生成报告／位流记录哈希；后续源码或产物变动会使旧证据失效。
MCP 仍只提供固定构建与已有检查／引脚操作，没有增加任意 shell/Tcl 或烧录接口。

这些改进提高可观测性、减少无效重跑，不能保证 Gowin 布线算法本身变快，也不能自动修复负时序余量。

## 一、本方案的第一铁律：保护 +0.054 ns

资源余量充足，时序余量不足。**所有新功能必须避免进入 audio_clk 域的关键路径。**

具体要求，每一项都必须在实施时满足：

1. **新模块一律挂在独立时钟域**，通过已有的 CDC 机制与音频域交互，
   不直接读写 `av_top` 中 audio_clk 域的组合逻辑。
2. **不新增 audio_clk 域的高扇出信号**。需要跨模块的控制位，
   先寄存再分发，参照现有 `poly_*` 控制束的写法。
3. **每一项功能单独综合、单独 P&R、单独记录时序**，不叠加提交。
   若某项使最差建立余量低于 +0.03 ns，该项必须回退或重做，不得合入。
4. 交付基线 `stage32_seed2` 的实际 `impl/pnr/cmd.do` 为
   `place_option 2 / route_option 2`，+0.054 ns 属于这次构建；
   后续候选默认仍用 `place_option 3 / route_option 2`，两者不可混记。

## 二、禁止事项（来自已付出代价的实测）

1. **不得使用 `syn_maxfan` 处理线延迟主导的路径。**
   stage29 对 `setting_mode` 施加后违例由 22 增至 750；
   stage33 对 `lane_allocate` 施加后被人工停止，未取得最终时序。
   stage33b使用的是消除重复门控的不同改动，不能也归因为新增syn_maxfan。
   两者都未完成，不足以证明卡死或确定最终布线结果；后续不再新增该类属性试验。
2. **不得为换取时序余量而改 PLL 分频。** 实算需将采样率降至约 47617 Hz
   （偏差 0.8%）才能换得约 +0.15 ns，代价是 ADSR、滑音、颤音 LFO、
   八弦调音表、272 组延迟基线与全部 CSV 捕获重做。
3. **不得删减回归套件。** stage31 曾将 73 项删至 61 项，
   其中包含八条物理弦的全部测试与共享波表的负向用例；
   该套件无法保护其自身主张的 72 单元。新增功能只增不减，并补对应用例。
4. **不得在同一构建目录并发运行两个 gw_sh。** 产物会交叉污染且无法归因。
5. **不得使用 `%TEMP%` 作为构建目录。** 2026-10-10 该目录被整体清理。
   使用 `E:/Gowin/workspace` 下的 ASCII 路径，
   P&R 结束后立即将报告复制进 `artifacts/`。

## 三、开发顺序与验收标准

按风险从低到高排列。每项完成并通过 P&R 后才启动下一项。

### 第一项：WS2812B 灯带驱动（36 颗）

第三版硬件已打板，当前 `rtl/` 下无该驱动，不实现则键盘灯光不可用。
对应赛题拓展 3 的 LED 演奏指引与拓展 4 的脱机曲目指引。

- 接口：B16 数据、B15 缓冲使能，共 2 个 IO（见第三版引脚文档）。
- 时序：800 kHz 单线协议，T0H/T1H 需按器件手册确认，不可凭记忆写。
- 时钟域：使用 sys_clk 或 pixel_clk，**不要用 audio_clk**。
  亮度数据来自现有 `status_payload` CDC 通路，不新增音频域逻辑。
- 数据源：复用 `held_note_mask`（12 位，已存在）映射到 12 键 × 3 灯。
- 验收：新增至少 2 个 testbench —— 位时序逐拍检查、36 灯级联复位间隔；
  整机 P&R 后最差建立余量不低于 +0.03 ns。

### 第二项：GT911 触摸（I²C）

硬件已确认：Dock J6 为 FPC-6P-0.5mm，金手指朝下，
引脚 1 RST / 2 VDD / 3 GND / 4 INT / 5 SDA / 6 SCL，
板上 SDA/SCL 已有 5.1 kΩ 上拉（R192/R193）。
FPGA 侧对应 `LCD_CTP[3:0]` = W16/U16/T16/T15，均为 3.3 V，当前未被占用。

- 实现一个 I²C master 状态机，速率不超过 400 kHz。
- **上电时序决定从机地址**：RST 拉低、INT 置低，延时 10 ms 后拉高 RST
  得到 0x5D。INT 与 RST 必须由 FPGA 驱动，不可悬空。
- 时钟域：sys_clk。坐标经现有 CDC 机制送入控制状态机。
- 验收：I²C 时序 testbench（含 ACK/NACK 与超时）、
  地址选择时序 testbench；整机 P&R 余量同上。

### 第三项：HDMI 输出（已购10.1寸1024×600）

2026-10-11 按 Dock31005 SOM 连接器及 PG484A 核对：TMDS 差分对为
D0=J14/H14、D1=J15/H15、D2=K17/J17、CLK=G15/G16（正/负，Bank3 3.3V）。
此前记录的 AA22/AA23 等来自 HDMI 页旧标注，不适用于当前 138K PG484A，已纠正。
仅串 100 nF 隔直电容，中间无编码芯片，**不依赖 DDR3**。
官方示例中的 `camera_hdmi_inst/u_ddr3` 是摄像头帧缓存所需，与 HDMI 输出无关。
上述 8 个引脚当前均未被占用。

画面与现有 7 寸 RGB 屏一样逐像素实时生成，不需要帧缓冲。

- 新增模块：TMDS 8b/10b 编码、10:1 串化（Gowin 原语 `OSER10`）、
  1024×600 时序参数（参照 `lcd_timing_800x480.v` 的写法）。
- 新增一个 PLL（板上 12 个，当前用 2 个）。
- **固定开发分辨率：1024×600**。用户于 2026-10-11 再次确认已购规格，
  HDMI 输出、界面布局与触摸映射均以此为目标，不安排其他分辨率扩展。
  像素时钟、消隐和同步参数按该 HDMI 驱动板资料或 EDID 确认；此前约
  51 MHz / 255 MHz 仅为估算，不能直接作为最终 PLL 配置。
  串行时钟仍须核对 C1/I0 速度等级下 OSER10 的器件限制。
- 双屏分工：7 寸 RGB 显示波形/频谱/李萨如（只读），
  10.1 寸 HDMI 做交互界面（选曲/调参/菜单），触摸只接 HDMI 屏。
- 验收：时序 testbench、TMDS 编码逐字节对照已知向量；
  整机 P&R 余量同上。

### 第四项：合唱效果器

赛题拓展 2 明文要求「混响、延迟、合唱」，当前缺合唱。

- 复用 `reverb_comb.v` 的延迟线与现有 LFO 基础设施，不新建。
- 这是唯一进入 audio_clk 域的一项，**风险最高，放在最后**。
- 实施前先单独综合评估对关键路径的影响；
  若使最差建立余量低于 +0.03 ns，改为在现有效果槽位内复用而非新增。
- 验收：PCM 逐样本对照（关闭合唱时与基线逐字节一致）、
  无削顶、无超期；整机 P&R 余量同上。

### 第五项：ESP32-S3 UART 协议（拓展 4）

工作量最大，依赖 V3 硬件实测，放在最后。
赛题合规边界：乐器音频必须 100% 由 FPGA 实时合成，
S3 仅承担语音助手与 BLE 数据通道，其语音经独立 I²S 功放与独立喇叭，
不进入 FPGA 合成链路。**演示时应能单独关闭该喇叭以证明这一点。**

## 四、每项功能的标准流程

```
1. 实现 RTL + 对应 testbench
2. 注册进 sim/run_dynamic_regression.ps1
3. 完整回归：pwsh sim/run_dynamic_regression.ps1 -Jobs 12
   （73 项约 3.5 分钟；必须全过且零失败，否则不得进入下一步）
4. 综合：gw_sh scripts/syn_only.tcl fpga_instrument_av.gprj
   记录 T_Lut / T_Register / T_Bsram / T_Ssram / DSP 各项
5. P&R：place_option 3 / route_option 2，timeout 不低于 7200 秒
6. 读时序：建立违例须为 0，记录最差建立/保持余量
7. 报告复制进 artifacts/，记录位流 SHA256
```

**不得跳过第 3 步直接综合，不得跳过第 6 步直接宣称完成。**

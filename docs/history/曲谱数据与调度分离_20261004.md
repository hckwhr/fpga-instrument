# 第三阶段：曲谱数据与调度分离

目标是让歌曲内容不再写在播放状态机中，换一份合法曲谱数据就能复用调度和事件发送逻辑。本阶段仍保持当前《小星星》的显示、听感和启停操作。

## 数据路径

`song_score_twinkle → song_player → note_event_voice → DDS/ADSR → 效果器 → PT8211`

`song_score_twinkle` 是组合只读查表逻辑（不声称推断为 BSRAM）。`song_player` 不再实例化任何具体曲目模块，曲目与播放器在 `av_top` 连接。LCD 继续读取事件接收后的音符。

| 接口 | 方向（相对播放器） | 约定 |
|---|---|---|
| score_index[5:0] | 输出 | 请求下一起音的数据行；进入/重播时请求 0 |
| score_length[5:0] | 输入 | 0～63 个音符；0 表示空曲谱 |
| score_note[3:0] | 输入 | 0～11 音高类别 |
| score_octave[1:0] | 输入 | 0～2 八度 |
| score_force[6:0] | 输入 | 1～127 起音力度 |
| score_duration[15:0] | 输入 | 音符开始到下一音符开始的采样数，包含末尾释放间隔 |

接口全部位于 audio_clk 域，是组合读端口，没有读请求/应答周期。曲谱必须在一次演奏期间保持不变；未来曲谱 RAM 需定义读延迟和换曲提交时机，不能把同步 RAM 直接接在这里。

播放器原参数 `QUARTER_SAMPLES` 仅用于推导释放间隔（参数范围 4～32767），实际每行时长来自曲谱。生产值的释放间隔为 7200 采样，约 150 ms；保持原 ADSR 收尾余量。16 位时长最大 65535 采样，约 1.365 s。当前不支持独立休止行，长休止和更长音符留待后续扩展。

## 边界处理

第一次起音和重播显式读取第 0 行；后续读取下一行。结束由曲谱长度控制，不再写死第 41 号音符。空曲谱、越界或非法音高/八度/力度/过短时长会结束演奏；若前一音正在播放，先按原计划发送 OFF 并等待剩余时长再结束，不留下保持音。

ON 中的八度、力度和音高均锁存在事件寄存器；预读下一行不会污染当前待发事件。背压、音符身份和 flush 规则沿用第二阶段。当前非法行与正常结束都显示结束状态，没有添加诊断菜单。

## 验证

- 正式《小星星》逐行 42 音符、48 拍及完整 PCM 比对。
- 另一个三音符测试曲谱以 E 音开头，使用不同八度、力度和 20/28/36 采样时长，在不修改播放器的情况下验证首音、结束长度、ON/OFF 时刻。
- 从每个测试行重播；正式曲谱从 G 音重播回 C。
- 空曲谱、非法首音、过短时长、非法后续行安全结束。
- 原有事件背压、停止/重播取消、音源、LCD、效果器及 UART 回归。

本轮首版拆分曾在中途重播时读取旧行，新加回归明确复现失败后修正。交付只使用修正后的源码和最终构建，不使用首轮位流。

最终结果见 `artifacts/note_event_stage3_20261004/validation.md`。当前仍为单声部内置歌曲，不等于已经支持任意歌曲、曲谱上传或多轨伴奏。

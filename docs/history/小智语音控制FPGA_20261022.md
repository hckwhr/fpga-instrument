# 小智语音控制 FPGA：S3 通用套件第一版

## 范围与底本

用户改为使用 ESP32-S3 开发板、INMP441、MAX98357 的通用小智接线测试，
不使用 V3 PCB。FPGA 保持刚烧录验收的 stage62，不修改 RTL、时钟或引脚。
新固件按 N16R8 编译；2026-10-23 两块实板均已核实为 16 MB Flash、8 MB PSRAM。

官方源码已下载：

- `firmware/xiaozhi-esp32`：官方 HEAD `7e69845d818553ac045efbcde746b22bef6eecf6`，
  要求 ESP-IDF >=6.0.1，保留作对照，未修改。
- `firmware/xiaozhi-v3`：实际适配底本 v1.9.4，提交
  `3ced7709c65a39494f5684e99111854a5bcbd8c7`，要求 IDF >=5.4.0；使用本机已验证的 5.4.4。
  目录名是最初接入时的名称，实际新增板型是 **fpga-bread-s3，不是 V3 PCB**。

## 已阅读的实际调用链及实现选择

1. `main/main.cc` 初始化事件循环/NVS，调用 `Application::Start()`。
   本板型关闭上游 NVS 初始化失败时的自动擦除，保留已有配置与排错证据。
2. `main/boards/common/wifi_board.cc` 管理热点配网、保存 SSID、联网与 Wi-Fi 节能。
   无配置时进入小智 AP 配网，连接成功后继续启动流程；不在源码硬编码密码。
3. `main/audio/audio_service.*` 的输入任务、输出任务、Opus 编解码任务独立运行。
   `NoAudioCodecSimplex` 对应通用接线：麦克风 16 kHz、喇叭 24 kHz，I²S 时钟分离。
   本地 ESP-SR 唤醒之后，经 Wi-Fi 的 MQTT/UDP 或 WebSocket 连接服务进行对话。
4. `application.cc` 根据 OTA/激活服务返回的配置选择网络协议；入站 `type=mcp`
   交给 `McpServer::ParseMessage()`，并非从 `stt` 或聊天文本用关键词猜测命令。
5. `mcp_server.cc` 注册工具、校验参数后用 `Application::Schedule()` 在主循环调用工具。
   因此本次工具**不阻塞等待串口**，而是返回 ticket，后续通过 result 工具查询。
6. `firmware/esp32s3-bridge/main/main.c` 保持 NimBLE host + 10 ms pump 为 UART 唯一拥有者。
   新入口 `instrument_bridge_start()` 供小智板型调用，避免第二个 app_main 或重复 NVS 初始化。
   小智的录音、网络任务不直接操作 UART，也不修改 BLE bridge_core 状态。
7. FPGA stage62 的 `hc05_commands.v` 虽然文件名沿用 HC05，实际是通用有线短指令端点。
   支持 `PING/PLAY/STOP/STATUS/HELLO`，不支持任意音色、音量或曲名选择。
   `av_top.v` 中 remote_song_stop 同时进入上传播放器 local_stop，故短 STOP 能停止上传播放；
   但短 PLAY 启动的是内置演示，短 STATUS 也不能替代上传协议 SONG2 STATUS。

## 实际改动

- 新增独立 `fpga-bread-s3` 板型，完整接入 Kconfig、CMake、config.json、板级源码。
- 通用麦克风 WS/SCK/SD=4/5/6，功放 DIN/BCLK/LRC=7/15/16；可选 OLED=41/42。
- UART1 TX=17、RX=18、9600 8N1；取消原通用板 GPIO18 的 LampController 示例。
- 保留 BOOT 对话、可选按住说话/音量键；无 OLED 时使用 NoDisplay。
- 小智构建不执行原 V3 固件的 GPIO39 功放静音，GPIO39 在通用板是音量减键。
- BLE 名称“行者无疆”、NUS UUID、整行队列、曲谱/采样数据透明转发保留。
- 新增纯 C `voice_core`：仅允许已实现命令、完整回复校验、拒绝错误 ACK、3 秒超时、
  边界/CRLF 检查。没有 FPGA 应答不能返回 confirmed，没有自动重试播放。
- 新增非阻塞 MCP 工具：`self.fpga.ping/play_demo/stop/status/result`。
- 与 BLE 明确互斥：上位机连接时语音命令返回 busy；断开后排空至少 3 秒再接管。
  语音事务中暂停广播并拒绝延迟到达的新连接；结束后排空回复再恢复广播。
- 原独立 BLE 工程默认没有 `BRIDGE_WITH_VOICE`，保留原 app_main 及 V3 接线行为。

## 接线与首轮测试

| S3 | FPGA Tang Mega / stage62 |
|---|---|
| GPIO17 TX | A20 RX（Dock J13-15） |
| GPIO18 RX | A21 TX（Dock J13-17） |
| GND | GND（例如 Dock J13-12） |

两边各自供电、共地，只接三根 3.3 V 信号/地线。不接 RS232 电平，不互接 5V，
不能与 V3/其他 S3 的 TX 同时并接驱动 FPGA RX。

固件烧录且完成小智配网/激活后：先断开电脑 BLE，等 3 秒，再唤醒并说
“检查 FPGA 是否连接”“让 FPGA 播放内置演示曲”“停止 FPGA 播放”。
结果以匹配的 FPGA 应答和实物声音分别验收。电脑 BLE 上传仍需随后重连实测。

尚未支持：语音播放上传曲谱、按任意歌名点歌、修改 FPGA 音色/音量；
小智自身喇叭的音量工具不能当作 FPGA 音量控制。当前没有硬件回声参考，
不宣称 FPGA 大音量播放下可可靠声学打断，也没有宣称完全离线识别。

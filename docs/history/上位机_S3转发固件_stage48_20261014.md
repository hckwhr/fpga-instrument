## 交付

源码：`firmware/esp32s3-bridge/`。硬件依据 `docs/hardware/第三版封装与引脚分配.md` 的 V3 ESP32-S3-WROOM-1-N16R8 配置：UART1 GPIO8/TX、GPIO9/RX，9600 8N1；GPIO18 高电平保持独立语音功放静音。原生 USB Serial/JTAG 用于日志与后续下载，不把日志送入 FPGA。

服务采用与网页一致的 NUS UUID，设备名 `FPGA-Instrument-V3`，单连接、Write With Response / Notify。实现完整行双向缓冲、有限队列、MTU 通知分片、超时和错误断开、断线清理及重新广播前的 UART 静默窗口。不生成 FPGA 成功应答，不在断线后自动播放或停止曲谱。

调用链：网页 `BleTransport` → NimBLE GATT 写回调 → 生产 `bridge_core.c` → UART1 → FPGA；应答原路通过 Notify 回传。状态由 NimBLE host 回调和 callout 串行持有，避免把阻塞串口发送放进 BLE 回调。具体容量、时限、在途命令不可撤销及迟到短命令边界见 [固件 README](../firmware/esp32s3-bridge/README.md)。

## 未验证与下一步

1. 未连接或烧录 S3；无线吞吐、真实 Notify 拥塞、UART 错误中断、手机后台、实际重连及电气状态未验证。
2. FPGA stage47 没有 V3 最终 CST/SDC、P&R 及时序验收位流；不能用现有 V2 stage42 的 A15/ADC CS0 接本 S3 UART。
3. 当前固件是 BLE 联调版本，未接入小智语音、Wi-Fi 或多来源指令仲裁，未实现 BLE 配对/接入授权；不代表 V3 全部功能固件完成。
4. 未生成安卓 APK。下一批复用现有网页与 Android 原生 BLE 桥，完成打包、文件导入和后台恢复软件，再做手机真机验收。
5. 断线时已送入 UART 驱动的整行仍可能被 FPGA 执行。3 秒静默窗口只隔离常规尾包，不能解决无限停钟后恢复的旧无编号短命令；该故障必须先恢复/复位 FPGA，主机不得宣称未执行。

本批按 ponytail 复用既有主机协议；按 ESP32 领域技能核对 S3 特有管脚；使用 build-idf 技能定位已安装 SDK 与首轮工具链错误，再用同版本完整工具链的原生 IDF 命令完成构建。没有修改 FPGA RTL 或上位机运行逻辑，因此未重跑无关的 FPGA 全回归和 P&R。

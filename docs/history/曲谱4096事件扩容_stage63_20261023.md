# stage63 曲谱扩容

## 目标与基线

将单次上传从 512 个事件、255 个旋律音符扩至 4096 个事件、2048 个旋律音符。单音起音/松开各一事件；伴奏也占事件，因此 2048 是总音符数上限，不是再加伴奏。长度不固定为秒数，默认整首识别仍限制 10 分钟。

基线 `work/v3_telemetry_stage62_20261021` 保留，候选为 `work/v3_score4096_stage63_20261023`。目标 Tang Mega 138K，SOM30354 + Dock31005，GW5AST-138C / GW5AST-LV138PG484AC1/I0，Gowin V1.9.12.03。基线报告 setup +0.088 ns、hold +0.188 ns、BSRAM 138/340；这些不是候选测量值。

保留 32 复音、8 物理弦、音色、表情、48 kHz PT8211、灯带与音频回传。引脚、PLL、复位、CDC 握手协议保持；显示状态和曲谱描述符的有效负载位宽扩展。对新网表重新证明原半速例外端点并无损压缩，不额外放宽时序。

## 容量与协议

上传暂存/已发布双缓冲之外，跨域播放另有一份不可变快照。三份曲谱的逻辑存储从 12 KiB 增为 96 KiB（每事件 8 字节），物理 BSRAM 使用以综合/P&R 为准。

模块默认 `SCORE_BITS=9, PROGRESS_BITS=8` 保留旧配置与回归；V3 产品顶层选择 `12,12`。地址 12 位，事件数 13 位可表示 4096；旋律总数和完整播放进度 12 位可表示 2048。

- 新版 CAPS：`13,4096,8,1`，仍使用 SONG2/ACK2 文本帧、每帧最多 8 个事件、原 CRC16。
- 新版接受 ABI12 短曲（512 事件、255 旋律）及 ABI13 长曲。旧板不接受 ABI13，上位机在发送前检查能力并阻止不兼容曲谱。
- ABI13 保持 64 位事件布局、24 位绝对时间、16 位独立音符 ID。低 8 位进度字段定义为完整旋律序号模 256；校验器维护完整计数验证此标签，播放器在每次接收旋律 ON 时维护完整序号。不得把低字节直接当整曲进度。
- ON/OFF 仍按唯一 ID 配对；同刻 16 事件、含尾音 16 声部与总力度 768 的实时准入规则保持。
- 短曲编译仍选择 ABI12，原 64 位字节序列不变；大于旧限制才选择 ABI13。
- 上传后不会自动播放；先完整校验并提交，PLAY 再复制快照、以原握手进入音频域。丢包重试不重复写入或发布；播放时的所有权锁保持。
- 后端等待由 100000 增至 1000000 系统时钟，避免 4096 事件完整扫描超过旧等待界限。
- LCD 与编号 STATUS 使用完整进度；短命令 STATUS 扩展到最多四位十进制，短曲输出格式保持。

S3 透明桥接无需扩展单帧缓冲：本轮增加帧数，单帧仍低于 256 字节。UART 保留 9600 8N1，扩容并不增加线速。主旋律识别精度与曲谱容量是不同问题；本轮不宣称音频转谱更准确。

### 串口速度与环形缓冲核查

用户询问提高波特率及环形缓冲收益。当前 9600 是继承配置：FPGA `av_top.SHARED_CLKS_PER_BIT=5208`，50 MHz / 5208 ≈ 9600；ESP32 `main/board.h` 的 `BRIDGE_UART_BAUD=9600`。不是器件硬件上限。

ESP32 已有两层环形缓冲：`main.c` 调用 `uart_driver_install(LINK_UART,2048,1024,64,...)`，ESP-IDF 5.4.4 的实际 UART 驱动使用 RX/TX ring buffer；`bridge_core.c` 用 `(head+count)%BRIDGE_QUEUE_LINES` 入队、`(head+1)%BRIDGE_QUEUE_LINES` 出队，双向各 4×256 字节整帧循环队列。小智固件通过 `main/CMakeLists.txt` 复用同一桥接源码。

FPGA `uart_line_router` 使用 255 字节同步读 BSRAM 整帧缓冲，不是环形队列。上位机 `score-upload.js` 逐个 `await exchange(...)`，每帧等 ACK 再发下一帧；因此单纯增加 FPGA 环形队列不会提高现有上传协议的并行度或串口线速，本轮不添加。

后续提速优先评估两端同时改为 115200：8N1 理论字节率由 960 B/s 变为 11520 B/s，串行占线时间缩至 1/12，端到端速度仍受 BLE 分包、调度和逐帧 ACK 影响。这是理论值，尚无 115200 双端固件及实物吞吐证据。本候选保持 9600，不能只更新一端，否则无法通信。

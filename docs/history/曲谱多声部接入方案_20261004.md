# 曲谱多声部接入：第六阶段检查结论与后续实现边界

本轮先拆分四声部混音器的关键组合路径，为后续音频扩展增加时序空间。下列多轨接入是后续方案，尚未实现。

## 当前真实接口

`song_player` 已输出带 occurrence ID 的 ON/OFF、音高、八度和力度，采用 ready/valid 与 flush 契约。接收端 `note_event_voice` 只保留一个声部。

`polyphony_bank_32` 有 32 条独立 DDS/包络通道和动态分配器，但入口仍是三按键 trigger/gate。释放通过 `voice_source` 对应物理按键，没有曲谱 occurrence ID。它支持按键复音，不是可直接接受任意曲谱 ON/OFF 的 MIDI 合成器。

因此不能仅将旋律触发接到三个按键线上就宣称完成多轨曲谱：相同音高的不同音符、延音中的重复起音以及被偷取声部的旧 OFF 都需要按 occurrence ID 处理。

## 接入顺序

1. 为现有 32 声部分配器增加通用事件入口，并为每个 lane 记录 occurrence ID。OFF 只释放匹配 ID；过期 OFF 不影响后来占用同一 lane 的新音。
2. 保留现有按键入口及完整回归；歌曲和手动演奏先采用互斥所有权，切换时 flush。暂不混合两个来源，减少释放归属歧义。
3. 增加一首“旋律＋低音＋和弦”事件曲谱，以共享拍时钟驱动各轨。事件按采样时间排序，同刻先 OFF 再 ON；在采样边界统一提交该时刻的变更。
4. 在原曲目入口提供独奏/伴奏对照，LCD 显示实际活跃声部数及曲目进度。证明同一旋律在不同时长、力度的伴奏声部上方独立进行，而非复制旋律频率。
5. 离线曲谱正确后，再接上位机导出和上传。蓝牙模块更换不应改动事件和音频数据通路。

## 必须先验证的细节

- OFF/ON 背压时，时间戳和 payload 保持，不能丢音或把两个同刻音错开一拍。
- 重复音高具有不同 ID；声部偷取期间收到旧 OFF、新 OFF、停止均有明确行为。
- flush 必须取消排队事件、停止新分配并释放所有歌曲声部；停止后再次播放不泄漏旧事件。
- 32 活跃声部不等于能在一个采样周期内处理任意数量的新事件。当前分配器满载扫描一次最多 32 lane，原九音批次约 316 个时钟；增加事件入口后需重新测量最坏事件吞吐量，不能沿用该数字作新协议保证。
- 若同刻事件批次无法在 1024 时钟内完成，需要提前调度/批次提交或改进分配路径；不能静默拖延音乐时间。
- 新曲谱应包含重叠长音、同音重复、休止、32 满载及第 33 音偷取、停止/换曲、不同 BPM 的验收。先复用已有包络和音色，音量按实际混音峰值检查。

第六阶段当前只改动四声部混音流水线；没有新增伴奏模式、通用 32 声部曲谱入口或歌曲上传。

## 第七阶段进展（2026-10-04）

已实现上述第 1、2 步的事件入口与互斥所有者，并将两首内置单旋律曲目接入真实 32 声部池。ON/OFF 按 16 位 ID 匹配；重复有效 ID 幂等忽略；旧 OFF 不会误停新声部。flush 取消在途分配及偷取中的新音，并自然释放；所有者切换清空旧状态。

单元测试包含 32 满载、33 音偷取、同音独立 ID、ID 回绕、非法数据、长时间 flush、重启及物理按键隔离。顶层以真实 1024 时钟采样间隔注入 C/E/G 三个独立事件，验证各自音高和单独释放；这不是板上新增伴奏模式。

测得空池 32 ON 为 128 时钟、满池 32 次替换为 1152 时钟，含测试发送开销。全部声部都在偷取淡出时可进一步背压，尚不能把 1152 称为任意状态最坏值。顶层当前单旋律显示观察器也仍限制每槽一个事件。

下一阶段应实现提前读取的时间戳事件批次、采样边界提交，以及能观察多声部的显示状态，随后再编配旋律/低音/和弦。不能直接把三个轨按顺序即时发送，便宣称实现同刻起音。

当前沿用声部池固定混音增益，完整歌曲单音 PCM 峰值 332，比第六阶段独奏通路明显轻；后续伴奏必须按整曲检查响度和满载余量。事件音沿用声部池渐起/保持/释放，不等同于四声部引擎完整 ADSR。未实现任意歌曲上传。

源码：work/polyphony_events_stage7_20261004。最终构建、时序和验证证据以该阶段 validation.md 为准。

## 第八阶段进展（2026-10-04）

已完成扩展前的控制关键路径优化。av_top.v 在 32 声部池入口统一寄存采样节拍、所有者、使能、flush 和手动参数；实时事件握手保留。手动路径整体延后一拍 audio_clk，约 20 ns。32 声部算法、音色和混音增益未修改。

Gowin 完整构建后的最差建立余量由 +0.005 ns 提高至 **+0.843 ns**，保持余量 +0.177 ns；未降低频率或放宽约束。最差路径已转移到声部相位至波形乘积。42 项回归通过，新增全声部一拍等价检查及一拍停止取消测试；两首曲目的完整 PCM 与第七阶段哈希一致。未烧录。

下一步仍是时间戳预调度、同刻事件统一提交和多声部显示观察器；本轮没有新增多轨伴奏。固定 32 声部混音下单旋律偏轻的限制仍在，需在编配阶段处理整曲平衡。

源码及验收：work/polyphony_control_stage8_20261004/validation.md。

## 第九阶段进展（2026-10-04）

已解除顶层单音元数据观察器“每采样槽只接收一个事件”的限制。它继续与真实声部池共同握手，但不再拖慢批量事件。单独使用的 note_event_voice 默认仍保留原单音 DDS 桥契约。

多音键盘改为读取声部池实际 lane 的持有音级并集，经扩展至 68 位的原有状态 CDC 整帧提交。相同音级多次触发、独立 OFF、旧 OFF 和偷取由同一份分配器状态决定；没有再造独立的 32 音显示分配器。释放尾音计入声部数但不继续按住键；三个八度折叠到 12 个音级。

43 项回归通过。新增生产顶层测试测得空池 32 ON 接收及分配 128 时钟，全部在下一个 1024 时钟采样边界前完成，并验证全部包络同时进入第一步 attack。异步像素域下通过三和弦、12 键、同音多 ID、偷取和整帧更新检查。两首完整单旋律 PCM 和四张旧界面截图与第八阶段相同。

这个测试有明确起始条件，不能代替任意到达相位、满载替换或背压下的截止期保证。分配器满载 32 次替换仍测得 1152 时钟，并有声部偷取淡出延迟。下一步仍需时间戳预调度和统一提交，随后才加入多轨编配。当前无新增板上伴奏/上传模式，未烧录。

源码与最终时序/资源证据：work/polyphony_display_stage9_20261004/validation.md。

第九阶段构建与引脚审计通过，但建立余量从 +0.843 ns 降至 +0.008 ns，保持余量 +0.188 ns。最差路径仍在声部相位至乘积，四声部引擎的 gain→pitch 路径也仅 +0.011 ns。后续多轨扩展前应先改善这些实际关键路径及显示逻辑映射；本轮是功能接入，不是时序优化。

## 第十阶段进展（2026-10-04）

已优化琴音插值和滑音关键算术：相邻波形点差值用常量表展开，滑音两种起点分别计算后选择；声部池插值与包络乘法之间增加配对寄存，混音运算多一拍内部延迟，采样周期不变。

最终建立余量 **+0.286 ns**、保持余量 +0.185 ns，DSP 从 161 降到 143；最差路径转移到分配器 search_index→best_gain。比第九阶段改善 0.278 ns，但没有恢复到第八阶段的 +0.843 ns，余量仍需关注。

46 项回归全部通过。新增全插值位置琴音对照、220000 拍滑音状态对照及 220000 拍完整声部池流水线对照；两首完整单旋律 PCM 与第九阶段相同。分配/相位/包络/显示状态不延迟，运算树严格多一拍。后续预调度须在采样边界前预留至少 8 拍稳定窗口，不能把刚分配的音符视为已进入输出。

下一步继续时间戳预调度与同刻事件提交，结合实际分配器搜索关键路径优化；再加入旋律、低音和和弦。内置曲目没有新增伴奏，尚未烧录。

## 第十一阶段进展（2026-10-04）

已实现《欢乐颂》独奏／伴奏对照。KEY0 循环小星星独奏、欢乐颂独奏、欢乐颂伴奏；其余启停、重播、四档速度及 S2 操作沿用。LCD 新增独奏/伴奏标识及实际声部计数，保留电平条位置。

伴奏为主旋律＋低音＋三音和弦，通过 song_ensemble 将旋律行事件展开后输入原 32 声部池。共 30 个旋律音、36 个伴奏音及匹配的 66 个 OFF；同组新音在共同采样边界起音。曲谱有五个持有声部，包含旧和弦尾音最多九路。

这轮选择**限定曲谱负载下的采样槽批次调度**，没有实现任意满载 32 音时间戳预调度器。只在采样槽前 1～15 个时钟接收批次，最多九个事件，等待分配器 ready 再结束批次；1000 拍未完成则停止清音。完整曲目测试最大批次耗时 25 个时钟，全部声部无需偷取。未来任意上传、多轨大编配和满载替换仍需先实现通用截止期机制，不能将本轮限额当作任意曲谱保证。

歌曲独奏/伴奏共用固定八倍增益，其他引擎不变；两首独奏 PCM 逐样本等于第十阶段八倍。完整《欢乐颂》独奏峰值 2656，伴奏峰值 6832，均无削顶、曲终静音。这是 RTL 仿真，不是实物听测。

## 第十二阶段进展（2026-10-04）

已用通用时间表播放器替换固定和声适配器。标准 MIDI 经现有共享解析器和新增离线限额检查生成同步 ROM，两首伴奏共用相同 RTL。每个音符拥有独立 ON/OFF ID、时间、音高、力度，支持跨轨重叠、同音不同实例及休止；曲目逻辑不再写在播放器中。

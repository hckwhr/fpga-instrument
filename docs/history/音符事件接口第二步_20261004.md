# 音符事件接口第二步：真实开启与释放

第一步的 `event_valid/gate` 只是旧输出别名。本步删除歌曲源的旧控制输出，正式走以下路径：

`song_player → valid/ready 音符事件 → note_event_voice → 原 DDS/ADSR → 效果器 → PT8211`

LCD 读取接收端生效的音符和保持状态，不提前显示尚未接收的事件。

## 接口约定

| 字段 | 含义 |
|---|---|
| `event_valid / event_ready` | 在 audio_clk 上升沿同时为 1 且 flush=0 时，恰好接收一个事件 |
| `event_on` | 1 为开启，0 为释放；持续发声期间不重复发送开启 |
| `event_id[15:0]` | 每次起音的身份，不是物理声部编号；同音高再次起音也使用新编号 |
| `event_note[3:0]` | 0～11 的音高类别，0=C；不是 MIDI 绝对音高 |
| `event_octave[1:0]` | 0～2，对应原有三个八度 |
| `event_force[6:0]` | 开启力度 1～127；零力度开启不接受为发声操作 |
| `event_flush` | 同步取消：优先于握手，发送端撤销待发事件，接收端清除起音与保持状态 |

普通释放只按 ID 匹配当前音符，不使用音高匹配。旧 ID 的释放不会停止后来起音的同音高音符。非法音高、八度或零力度开启会被接收并忽略，不改变当前发声音符。

编号仅在复位时归零，停止/重播/退出均不归零；16 位自然回绕。当前曲谱不存在跨回绕的延迟释放。未来接入外部队列时不能保留跨越 65536 次起音的旧事件；本协议还没有跨连接会话编号。

## 流控和取消

发送端只有一个待发槽，阻塞时保持 valid 和全部字段，暂停曲谱倒计时，禁止覆盖。接收端每个音频采样间隔最多接收一个事件，并避开 sample_strobe 上升沿；开启状态至少经过一次 DDS 采样机会后，才允许下一事件覆盖。生产采样周期有 1024 个时钟，本曲谱事件远慢于接口容量。

停止、重播、退出是共同取消边界。flush 是“阻塞时必须保持 valid/字段”规则唯一的运行中例外；必须同时送到发送端和接收端。它释放包络而不是直接把 PCM 截断；音高、力度保留供旧包络自然收尾。重播等待原有 7200 个采样的释放间隔后再开始。

有背压时曲谱会延长，因此当前还不是面向多轨同时事件的绝对时间调度器，也不承诺拥塞时保持原拍速。单声部接收器的新开启会替换旧音符，当前歌曲通过释放间隔避免带声换音；未来多声部歌曲需接入声部分配器，不能直接把该单声部桥当作 32 声部接口。

## 检查内容

- `tb_song_player`：42 对 ON/OFF 的顺序、身份和音高；48 拍时长；重复音、释放间隔、按键保持；开启和释放在阻塞时不丢失；停止/重播/退出取消待发音符。
- `tb_note_event_voice`：每采样间隔一次接收；连续同音高新身份；旧 OFF 不误停；编号边界、非法输入、flush 优先级与复位。
- `tb_song_top`：真实控制器、合成器、包络、效果器与 LCD，整曲无削顶、结尾归零，原有停止/重播/退出。
- `tb_hc05_top`：真实 UART 路径的播放、停止、重播及本地优先级仿真，不等于蓝牙硬件已联调。

用户可见曲目和操作没有增加。本步建立实际的事件传输基础；任意歌曲下载、多曲目、伴奏和跟练均留给后续阶段。

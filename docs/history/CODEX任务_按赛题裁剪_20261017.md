# Codex 任务：按赛题要求裁剪，一次做到可交付

## 一、必须先纠正的认知错误

此前所有收敛工作都建立在一个错误前提上：以为必须保住 72 个独立发声单元。

赛题原文（`.tmp_contest_2026.txt:438-442`）：

> 1、超高规模并行合成引擎。突破基础复音限制，实现复音数 ≥32，
> **或**单音加法合成分量 ≥32 路，**或**多条并行物理建模运算单元，
> 最大化发挥 FPGA 并行计算优势，提升振荡器整体吞吐量。

**是「或」，不是「和」。满足任意一条即达标。**

当前实现同时做了三条：32 复音 + 32 加法分量 + 8 物理弦 = 72 单元。
这是布不通和时序过不去的根本原因——为一个题目没要求的数字，
多塞了两套完整引擎。

本任务的目标是**完赛可演示**，不是把振荡器数量做到极致。
演示时听感上也分辨不出 32 与 72 的区别。

## 二、裁剪方案

保留 `polyphony_bank_32`（32 复音），它单独就满足拓展要求 1。
移除另外两套引擎。

### 移除清单

| 对象 | LUT | REG | DSP | 赛题依据 |
|---|---:|---:|---:|---|
| `u_partial_bank[*].u_partial`（32 加法分量） | 2169 | 1249 | 32 | 拓展 1 为「或」，32 复音已满足 |
| `strings[*].voice`（8 物理弦） | 9723 | 4440 | 40 | 同上 |
| **合计** | **11892** | **5689** | **72** | |

当前 Logic 72646、CLS 70%、setup −2.126、120 条违例。

### 为什么这一刀能同时解决两个问题

**资源**：Logic 预计降至 61000 以下，低于 stage32 布通时的 67979。

**时序**：54i 的 120 条违例中，**74 条终点在 `physical_string_bank/strings[*]`**，
25 条在 `pt8211_tx`。移除物理弦直接消掉 74 条，占总数 62%。
剩余违例的拓扑压力也会随布局宽松而缓解。

这是唯一一刀同时命中资源与时序的改动。

## 三、实施要求

1. **用参数开关，不要删文件。**
   `av_top` 增加 `ADDITIVE_BANK_ENABLE` 与 `STRING_BANK_ENABLE`，
   V3 完整版均传 0。保留模块与原有参数化路径，
   以便答辩被问到时可说明「架构支持，本版按赛题要求配置」。

2. **处理音源选择与并发自检。**
   - `rtl/av_top.v:391` 附近的 `pre_effect_audio_sample` 多路选择中，
     去掉 `string_sample` 与 `additive_test_sample` 分支。
   - 72 单元并发自检（`concurrent_test_source`）失去另两套引擎，
     改为 32 复音自检，或整体关闭。
     **关闭是可接受的**：赛题「现场验证要求」只要求
     「测试模式下输出多路不同频率音频，频谱可观测对应数量独立谱峰」，
     32 路同样满足。
   - 菜单中「琴弦」模式项一并移除，避免选中后无声。

3. **回归套件相应调整。**
   物理弦与加法分量相关用例改为模块级独立测试，不进整机套件。
   **套件数量变化必须在交付说明中写明**，不得静默减少。

4. **保留全部其余功能。**
   12 路压力键、摇杆、旋钮、菜单、LCD、键灯、效果器、频谱、
   UART 上传链、PT8211 输出、三维以上表情、两种以上音色——
   这些都是赛题明确要求或已实现的加分项，一项不减。

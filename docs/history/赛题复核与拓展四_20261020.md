## 到板演示

1. 断开主机，选择内置曲目，检查音频、LCD进度和LED跟随，确认重新上电也能使用内置曲目。
2. S3需使用stage51实际引脚固件：GPIO17 TX→FPGA A20 RX/J13-15，GPIO18 RX←FPGA A21 TX/J13-17，9600 8N1、3.3V逻辑、共地。A15是ADC时钟。S3当前是否已烧入该固件尚未确认。
3. 本地服务网页，选择BLE，连接 `FPGA-Instrument-V3`，使用默认NUS UUID。先识别，再检查上传能力；收到真实CAPS后才上传。
4. 先用 `host/instrument-web/test/fixtures/fpga-scores/twinkle.mid`，选择旋律轨、上传，等待COMMIT ACK，再按上传曲谱播放。
5. 观察音频/LED/LCD后断开连接，确认仍继续且自然结束；再连接查询状态。额外验证菜单抢占/本地停止，避免挂音。

上传曲谱在RAM，断电丢失；内置ROM曲目不依赖上传。容量512事件字，ON/OFF各占一字，并受声部尾音/力度预算约束。网页本地曲谱库不是FPGA永久存储。

**灯光与键位限制**：当前曲目灯光来自 `polyphony_bank_32` 的 `voice_note` 音级掩码，经 `keyboard_light_status` 直接显示为C、C♯、D……B的12个位置；钢琴模式的实际12键则采用白键音阶并跨八度。因此本次通过的是十二音级灯光序列，尚未验证钢琴模式的物理按键指引对应；钢琴模式下不能把该灯光序列当作准确的按键提示。当前演示应先使用半音排列的同音色模式；钢琴白键模式的曲谱到键位映射另需实现与验收。

后续优先事项：完成真实S3/FPGA/灯带联调及上述现场量测。独立APK、在线曲库服务、键位自定义、录音回传另行开发，不把它们混同于已完成的本地网页功能。

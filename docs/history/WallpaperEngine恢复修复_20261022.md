# Wallpaper Engine 动态壁纸恢复修复

## 定位

修改限定在 Wallpaper Engine 导入链路，本地视频背景代码未修改。

1. `handleWallpaperEngineHostBoundsChange` 原先直接以 `document.hidden` 拒绝恢复。WE 原生窗口捕获可使 Chromium 遮挡状态滞后；桌面窗口已经可见时，Scene 仍一直停留在准备恢复状态。
2. WE 视频媒体的播放与恢复同样直接依赖页面隐藏状态，且没有跟随原生窗口状态变化补做恢复。
3. 已运行 Scene 的 capture ended/error 原先只在“已经处于重连”的情况下重试，首次运行中断会直接退回预览。
4. 旧播放请求在验证其代次之前取消重试，可能取消新壁纸的播放重试；失败回退后也可能残留准备恢复标志。

这些是代码和可重复测试确认的故障路径，尚未抓到用户所用具体 WE 场景消失时的现场日志，不能断言涵盖所有原因。

## 修改

- 桌面恢复使用原生窗口状态；保留主进程已验证可见的恢复通知，以处理窗口状态通知先后差异。浏览器环境仍遵循页面可见性。
- WE 视频媒体随原生窗口最小化/恢复暂停和继续，避免依赖缺失的页面可见性事件。
- 已运行 Scene 的连接故障复用现有重连流程，最多三次；初次启动失败不自动反复重试。
- 释放媒体前失效旧回调，重连定时器检查当前代次与壁纸 ID，防止切换壁纸后旧任务覆盖新选择。
- 回退预览时清掉准备恢复标志；旧播放请求不再取消新请求的重试。

## 验证

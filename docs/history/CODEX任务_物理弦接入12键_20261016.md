# Codex 任务：物理弦接入 12 压力键

> **排期约束：本任务不属于资源收敛，不得与 `docs/CODEX任务_资源收敛_20261016.md` 混做。**
> 必须在该收敛任务取得可交付位流之后才开始。本任务会增加资源，
> 在 514 条未布通尚未解决前实施只会掩盖归因。

## 一、问题

`rtl/av_top.v:342-343`：

```verilog
assign v3_live = V3_INPUT_ENABLE && v3_ready && !score_active && !setting_mode &&
    !setting_key_pressed && !audition_active && !self_test_active && !string_mode;
```

`v3_live` 条件含 `!string_mode`。菜单选「琴弦」后 `v3_live` 为假，
12 个压力键整体失效，八条物理弦只能由板载三键触发。

后果：八弦物理建模是本作品的旗舰算法，也是赛题 72 个独立发声单元中的 8 个，
却无法用真正的键盘演奏，也拿不到压力键的力度信息。

## 二、接口为什么卡在三键

`physical_string_bank` 当前入口为 3 位 gate 加一个共享根音：

```verilog
input wire [2:0] voice_trigger, voice_gate;
input wire [3:0] note_select;
input wire [1:0] octave_select;
input wire       keymap_select;
```

真正的限制不是触发位宽，而是**释放判定**。
`rtl/physical_string_bank.v:110-122` 中每条弦记录一个 3 位归属掩码：

```verilog
else if(fire) begin
    reserved[g]<=1; gate_mask[g]<=event_mask;
    released[g]<=((voice_gate & event_mask)!=event_mask);
end else begin
    if(active_voices[g]) reserved[g]<=0;
    if((voice_gate & gate_mask[g])!=gate_mask[g]) released[g]<=1;
end
```

`gate_mask[g]` 宽度与 `voice_gate` 绑定。按住与松开完全由这三位电平推导，
没有音符事件语义，因此接口无法简单加宽。

## 三、已有的可复用资产

**该模块内部已经有一个 8 目标音符分配器**，不需要重写：

`rtl/physical_string_bank.v` 的 `IDLE → PREPARE → SEARCH → PICK → WRITE` 状态机
已实现「给定音符，选一条弦」的完整逻辑：优先空闲弦，其次已释放弦，
再次电平最低弦（`eligible` / `better` 判据，第 42-44 行）。
它缺的只是一个音符来源。

**12 键事件生成器已存在且已验证**：
`rtl/keyboard_note_events.v` 接收 `keys[11:0]`，按
`rtl/note_event_contract.vh` 的契约产生 ON/OFF 事件，
带 ready/valid 握手，并做状态对账（键已松开但事件尚未被接收时，
仍会补发对应 OFF）。该模块当前服务 `polyphony_bank_32`。

**OFF 匹配有现成范式**：
`rtl/polyphony_bank_32.v:419-428` 用 16 位事件 ID 做归属判定，
并把等值比较拆成 8 组 2 位并行比较（`id_pair_equal`）以避开长进位链，
其注释记录了该拆分的原因。

## 四、两种架构

### 方案 A：加宽 gate 接口（3 位到 12 位）

`voice_trigger`、`voice_gate`、`gate_mask[g]` 全部加宽至 12 位，
并为每键提供独立音符。

**不推荐。** 现有和弦逻辑依赖共享根音加偏移
（`rtl/physical_string_bank.v:66-70` 的 `root` 与 `chord_source`），
12 键各带音符后这套映射需要重写；
`gate_mask` 加宽会使 8 条弦的比较逻辑增大四倍；
且与 `polyphony_bank_32` 的事件契约不统一，两个库各一套语义。

### 方案 B：增加事件入口（推荐）

给 `physical_string_bank` 增加一组与 `polyphony_bank_32` 完全相同的事件端口，
由同一个 `keyboard_note_events` 实例按模式分发。

```
                              ┌─ string_mode  → physical_string_bank（新事件口）
keyboard_note_events ─ event ─┤
      (keys[11:0])            └─ 否则         → polyphony_bank_32（现有事件口）
```

**复用点**：8 目标分配器、12 键事件生成器、事件契约、ID 比较范式，四项全部现成。
**新增**：每弦一个 16 位 ID 寄存器与其比较逻辑，以及事件到 `PREPARE` 的接入。
**附带收益**：`event_force` 由 `key_forces` 产生，压力灵敏度直接可用，
不需要另接 `force_value`。

## 五、方案 B 实施要求

### 1. 端口

按 `rtl/note_event_contract.vh` 增加，命名与 `polyphony_bank_32` 一致：

```verilog
input  wire event_mode, event_valid, event_on,
input  wire [`NOTE_EVENT_ID_WIDTH-1:0] event_id,
input  wire [3:0] event_note_in,
input  wire [1:0] event_octave_in,
input  wire [`NOTE_EVENT_FORCE_WIDTH-1:0] event_force_in,
output wire event_ready,
```

注意模块内已有 `event_note`、`event_force` 两个内部寄存器名，
新端口须另行命名以免遮蔽。

### 2. 事件模式下的分配

`event_mode` 为真时：

- `IDLE` 改由 `event_valid && event_on && event_ready` 触发，
  不再读 `voice_trigger`。
- `root` 取 `event_note_in` 加 `event_octave_in` 对应的八度基，
  不经和弦偏移；`member` 直接进入单音分支（`remaining` 只置一位），
  和弦展开仅在 3 键模式保留。
- `event_force_in` 写入 `batch_force`。
- `event_ready` 仅在 `state==IDLE && enable && event_mode && !sample_strobe` 时为真，
  与 `polyphony_bank_32.v` 的 `event_ready` 条件保持一致，
  避免采样沿与事件接收竞争。

### 3. 释放语义

事件模式下 `gate_mask` 不再可用，改为按 ID 归属：

- 每条弦增加 `string_id[g]`（16 位）与 `string_id_valid[g]`，
  在 `fire` 时写入当次 `event_id`。
- OFF 事件（`event_valid && !event_on && event_ready`）到达时，
  对 ID 匹配的弦置 `released[g]`。
- ID 比较**必须**采用 `rtl/polyphony_bank_32.v:419-424` 的 8 组 2 位拆分写法，
  不要写成单个 16 位等值比较。该注释已记录原因。
- 3 键模式的 `gate_mask` 路径原样保留，不得改动。

### 4. 顶层分发

`rtl/av_top.v`：

- `v3_live` 去掉 `!string_mode`，改为按模式决定事件去向。
- 事件总线（valid/on/id/note/octave/force）同时接到两个库，
  由 `string_mode` 选择哪一个库的 `event_ready` 回送给
  `keyboard_note_events`，另一个库的 `event_mode` 置 0。
- **两个库的 `event_mode` 必须互斥**，不得同时为 1。
- 板载三键在事件模式下仍保留菜单与模式切换职能。

## 六、验证要求

1. **12 键到弦的分配专项**：12 键逐个按下与松开，断言
   每次 ON 落到一条弦、OFF 只释放 ID 匹配的那条弦；
   超过 8 键同时按下时按既有 `better` 判据抢占，不得出现双重归属。
2. **ID 匹配负向用例**：构造「按下后在事件被接收前松开」与
   「同一音高两次起音」两种情形，断言不会出现
   新起音被旧 OFF 误释放。`keyboard_note_events` 的状态对账
   保证 OFF 必定补发，该性质须被覆盖。
3. **3 键路径不回归**：板载三键与曲谱、试听路径的全部既有用例逐字节一致，
   包括 `gate_mask` 释放行为。
4. **整机用例从引脚开始**：压力键引脚电平到 PT8211 输出，
   覆盖琴弦模式下的发声、释放与力度差异。
   不得只在事件总线注入激励（stage53c 的教训）。
5. **力度实测**：同一音高在不同压力下的 PCM 包络差异需量化记录，
   不得只声称「压力生效」。
6. 完整回归全过、综合无锁存器、P&R 建立与保持违例为零、
   setup 不低于 +0.03 ns、45 引脚与时钟审计通过。

## 七、资源预算

新增约 8 条弦乘 16 位 ID 寄存器等于 128 FF，加 8 组拆分比较的 LUT。
事件接入本身复用现有状态机，不新增分配器。

**实施前必须先确认收敛任务已把 Logic 降到 72000 以下并留出余量。**
若本任务使 Logic 回升越线，优先回退本任务而非削减收敛成果。

## 八、不做的事

- 不改 `physical_string_voice` 的波导算法、调音表或延迟 RAM。
- 不改 3 键模式的和弦映射与 `gate_mask` 释放路径。
- 不把两个声部库的事件模式同时打开。
- 不为本任务调整时钟、采样间隔或 SDC。

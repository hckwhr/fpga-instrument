# 板端短命令应答接入记录

日期：2026-10-14。继本地曲谱库之后，按拓展四的通信探路顺序接入现有板端短命令。早期阶段只改网页、测试及文档；stage46 已在独立候选增加共享 UART 分流/仲裁 RTL，但仍未接入生产顶层、S3 固件、引脚或烧录。

## 源码依据

协议按 `work/fsr_latency_stage42_20261013/rtl/hc05_link.v` 实际字符串及逻辑实现，网页模块为 `host/instrument-web/src/device-session.js`。

`HC05` 是旧线协议的标识，不证明连接介质是 HC-05。V3 仍采用 ESP32-S3 内置 BLE → 唯一 3.3V UART → FPGA；若 S3 透明转发下表协议，可复用此网页适配。S3 GATT 的最终 UUID 尚未冻结，网页中的 NUS 是可配置默认值。

## 已接入的协议

所有命令大写 ASCII，LF 结尾；接收也接受 CRLF。一次只允许一条请求等待应答。未实现能力查询 `CAPS` 和整曲 `SONG1` 的固件，不因网页出现新按钮而获得这些能力。

| 命令 | 接受的实际应答 | 网页行为 |
|---|---|---|
| HELLO | `OK,HC05,1,9600,8N1,DEMO=TWINKLE+ODE` | 识别短命令 v1，允许查询与控制内置曲目；整曲上传能力为 false |
| PING | `PONG` | 表示收到响应，不代表歌曲提交或开始演奏 |
| PLAY | `OK,PLAY` 或 `ERR,LOCAL` | 确认请求获应答或显示本地设置/停止键阻止；不猜测播放位置 |
| STOP | `OK,STOP` | 确认停止请求获应答；不把它当作模拟音频静音的测量证据 |
| STATUS | `STATUS,SETTING` / `STATUS,MANUAL` | 显示最近一次设备回报的模式 |
| STATUS | `STATUS,PLAYING,ddd/ddd` / `STATUS,STOPPED,ddd/ddd` | 显示最近查询的条目计数；不换算成秒，不用浏览器计时猜测进度 |
| 任意请求错误 | `ERR,BUSY/FRAME/LINE/LOCAL/TIMEOUT/COMMAND` | 拒绝该请求并显示对应原因，不显示成功 |

UI 操作顺序：连接 BLE 或串口 → 点击“识别设备” → 查询状态或播放/停止内置曲目。页面和曲谱库从不自动发送 PLAY。网页当前曲谱不等于板上当前内置曲目；该协议不支持网页选曲、改变板端速度或上传用户歌曲。

## 应答与恢复约束

- 传输 API 写入完成、设备应答是两件事；必须同时完成本次写入并收到对应完整应答，才认为请求成功。应答先到而写入后失败时仍报失败。
- 未匹配命令的应答、回显、未请求的状态、未知协议版本不更新已确认状态。接收允许 BLE 任意拆包、多行粘包、串口字符串回调。
- 网页层通信日志独立保留原始文本，中文跨通知仍正确解码。FPGA stage46 共享 UART 的物理行缓冲最多 255 个 ASCII 字节，超长、非 ASCII、CR 后多余字符和半行超时均丢弃到下一 LF；SONG2 忙时整行丢弃并设置粘滞 `rx_dropped`，不会拼成新请求。
- 默认等待应答 3 秒。v1 没有请求序号，超时或发送失败后阻止新的结构化命令，要求断开重连并再次识别，不自动重试 PLAY。超时表示结果未知，不能推断板端未执行。
- 断线清空识别结果、最近状态和未完成请求；旧写入 promise 的晚到完成/失败不能修改新会话。网页显示“断开通信不代表停止演奏”。
- 手动通信测试独立为调试模式；一旦发送原始文本，本连接不再进行结构化控制，须重连识别。这样不会把手动命令的迟到应答认成控制按钮的应答。等待结构化应答时禁用原始发送。
- V3 S3 实现时应将 FPGA 应答原样转发，不在本地伪造同名 `OK,PLAY` 等成功应答。连接重建须清理旧会话转发缓冲；新协议需使用会话与请求编号才能支持可靠自动重试。

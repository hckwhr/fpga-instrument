# 自定义键位与演奏录音

电脑与 Android 在 FPGA 播放模式提供“我的演奏”入口。连接设备后点击“读取设备设置”，设备确认支持后即可修改键位或开始录音。该功能需要配套的 [演奏扩展 FPGA 工程](../fpga/performance/v3_hdmi_top.gprj)，旧版设备会提示更新。

## 十二键音高

按实体压力键从左到右排列，每键可选 C3—B5。提供 C 大调、半音阶、五声音阶预设，也可以逐键选择。松开所有键后点击“应用到实体键”，收到板端确认才表示生效。

音高设置适用于复音和物理弦演奏，保留音色、力度、滑音、弯音、颤音与效果器设置。两个键可设为相同音高，每个起音仍有独立身份，释放一个键不会误释放另一键。上传曲目的音高不受实体键映射影响。

App 保存编辑草稿；FPGA 设置在断电后恢复默认。重新连接时查询设备实际状态，不自动覆盖。使用“恢复板端默认”可以重新使用面板菜单原有的键阶规则。

## 真实演奏录音

点击“开始录音”，随后在实体键上演奏，最后点击“结束并回传”。完成后可以在 App 内试听，或保存 WAV。最长 60 秒，达到上限会自动结束；停止时补齐当前 20 毫秒音频块。

音源来自 FPGA 最终混音 PCM，包含和弦和效果器，不调用手机或电脑麦克风，也不是本地曲谱合成。为兼容现有 115200 串口，48 kHz 采样经两级四点移动平均、四倍降采样后，以 12 kHz 单声道 IMA ADPCM 回传，再解码为 16 位 WAV。它保留演奏中的真实音色变化，但不是无损录音，高频范围低于板端原始输出；不包含 DAC、功放和扬声器的声学特性。

录音期间保持应用在前台并维持连接。上传曲谱、联动采样和修改键位与录音互斥。断线、缓冲溢出、丢块或数据损坏会明确报告，本次不生成“完整录音”；此前已完成的录音仍保留。

## 工程原理

- `performance_uart.v` 负责 PERF1 请求、CRC、应答、录音续租和回传调度；键位经稳定数据握手，在音频引擎使能沿一次性提交。
- `performance_recorder.v` 通过只读 PCM 支路采集，经顺序 ADPCM 编码写入双缓冲；回传阻塞不会阻塞 DAC。
- 每块含 240 个采样，20 毫秒一块，编码后每行 196 字节，共 9800 字节/秒。串口为 115200、8N1，理论容量 11520 字节/秒。
- App 校验事务 ID、块序号、CRC 和预测器连续性。开始、停止与续租属于同一录音事务；旧事务不能停止新录音。
- 原 ESP32 桥接转发完整串口行；Android 请求较大 BLE MTU 和高连接优先级。实际 BLE 吞吐由手机、设备及无线环境共同决定，USB 仍可作为电脑端备用链路。

## 构建入口

在独立 ASCII 路径复制 `fpga/performance`，先执行 `sim/run_dynamic_regression.ps1 -Jobs 12`，再对 `v3_hdmi_top.gprj` 综合。完成综合后，执行 `scripts/prepare_performance_constraints.ps1`，用实际网表生成并检查压缩约束，最后以 place3/route2 进行 P&R。不要把复制来的旧约束直接当成新综合网表的依据。

电脑与 Android 共用 `host/instrument-web/src/performance-*.js`。先构建共用页面，再运行 `host/mineradio/tools/prepare-app.mjs`；电脑按 `build:fpga:dir` 打包，Android 按 `android/build.ps1` 打包。签名私钥与设备数据不进入仓库。
